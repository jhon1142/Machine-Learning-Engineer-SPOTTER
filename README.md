# SPOTTER -- Freight Rate Prediction

Predict the `posted_rate` (USD) for US freight loads given route, equipment, weight, date, and market signals.

## Problem

Given a freight load with known pickup/delivery cities, equipment type, weight, date, `market_index`, and `quote_signal`, predict the `posted_rate` in USD.

- **Train set:** 48,000 labelled loads -- Jan 1 to Oct 31, 2025
- **Validation set:** 12,000 unlabelled loads -- Nov 1 to Dec 31, 2025
- **Target:** `posted_rate` (continuous, right-skewed, USD)

## Approach

### 1. Data Cleaning

- **Negative weights (~6% of records):** confirmed as sign-entry errors via KDE
  comparison; corrected with `abs()` and tracked with a binary flag
  `weight_sign_corrected`.
- **Missing values:** `weight` (300 nulls) and `market_index` (374 nulls) imputed
  with the **training-set median only**. A `market_index_missing` flag preserves
  the missingness signal for the model.
- **EDA-only columns:** `rate_per_mile` and `distance_group` are dropped before
  the train-test split to prevent data leakage.

### 2. Feature Engineering

New features created by `add_features()`:

| Feature | Description |
|---|---|
| `bearing` | Direction of travel in degrees (0-360) |
| `delta_lat`, `delta_lon` | Absolute coordinate differences |
| `haversine_km` | Geographic distance (Haversine formula) |
| `dist_x_market` | distance x market_index |
| `dist_x_quote` | distance x quote_signal |
| `quote_x_market` | quote_signal x market_index |
| `dist_dry_van`, `dist_flatbed`, `dist_reefer` | Distance x equipment type |
| `month`, `quarter`, `day_of_week`, `day_of_year` | Temporal features from `date` |

### 3. Train / Test Split

- **80/20 random split** (`random_state=42`) -- 38,400 train / 9,600 test
- All transformers (imputer, scaler, encoder) are **fitted on the training
  partition only** and applied with `.transform()` on the test set, validation
  set, and December inputs
- The external validation set (Nov-Dec 2025) is never touched during development;
  it is the true temporal holdout

### 4. Models

| Model | Validation method | Notes |
|---|---|---|
| Linear Regression | Internal test 20% | Baseline |
| Random Forest | Internal test 20% | 300 trees |
| XGBoost | Internal test 20% | log-target, 1000 trees |
| LightGBM | Internal test 20% | log-target, num_leaves=63 |
| XGBoost + Optuna | 3-fold CV + test | 50 Bayesian trials |
| LightGBM + Optuna | 3-fold CV + test | 50 Bayesian trials |
| MLP Neural Network | Internal test 20% | 512->256->128->64, BatchNorm, Dropout |
| **Stacking Ensemble** | **5-fold OOF + test** | **Ridge meta-model -- final model** |

The target is log-transformed with `log1p` for all gradient boosting and neural
network models to reduce skewness and improve fit on lower-rate loads.

### 5. Stacking Ensemble (Final Model)

Base learners generate **out-of-fold (OOF) predictions** across 5 folds -- each
training row is predicted by a model that never saw it. A **Ridge meta-model**
(`alpha=1.0`) blends the four base-learner prediction columns in log-space.

## Key Findings

- **Route (pickup + delivery + equipment) explains 87% of rate variance** -- the dominant signal
- Date alone explains less than 1% of variance -- time-series methods add negligible value
- Flatbed commands the highest rates per mile; Dry Van the lowest
- `posted_rate` is strongly right-skewed (skewness ~2.1) -- log-transform is required
- Daily average rate autocorrelation at lag-1 = 0.33 -- moderate market momentum
